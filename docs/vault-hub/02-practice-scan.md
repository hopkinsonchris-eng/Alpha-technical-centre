# Phase 1 — Practice Scan

Researched 29 Sep 2026 by four parallel web sweeps (MLOps run tracking and
lineage; enterprise knowledge and RAG; oil & gas data platforms, evaluation
firms and literature mining; agent memory and multi-model cost engineering).
Every row cites a live source. The first table is the twelve practices that
matter most for us; the appendix keeps the rest.

## Appendix A — further practices considered

Grouped; each is a candidate for a later wave or a design rule rather than a build item.

**Versioning and lineage rules.** Content-hash versioning so identical re-runs collapse to one id (W&B). Status tags on versions (`draft/reviewed/approved/deprecated`) with gated promotion, e.g. "cannot mark final unless reviewer ≠ author" (MLflow, Neptune). Never delete or rewrite a run; supersede it, and never garbage-collect anything a deliverable references (Delta Lake time travel caveat). Stable GUIDs, not file names, as lineage keys; renames break lineage otherwise (Unity Catalog). Manual links allowed but marked `source: manual` (DataHub). Protected `main` plus a schema-validating GitHub Action, the lakeFS "write, audit, publish" pattern applied to run JSON. Small pointer records in git, large payloads in object storage (DVC); Git LFS only as an interim.

**Catalog and scorecards.** A `tool.json` beside each tool with mandatory owner and lifecycle (`experimental/production/deprecated`) and docs in the same folder (Backstage `catalog-info.yaml`, TechDocs). Scorecards that score every project against rules such as "run uses current tool version", "evaluation cites at least one run", "letter links to the run it quotes" (Cortex, Port). A `tools/_template/` golden path for new tools. Keep a Changelog format with an Unreleased section and a "what's new" badge in the Hub.

**Knowledge and retrieval.** Sanitise at project close: a redacted method note is the only route by which client content becomes firm-wide (BCG, McKinsey). Foundry-style ontology: object types, properties, link types and actions, with markings that propagate through lineage. Exhaustive "grid" jobs (every document × one structured question) for coverage questions rather than top-k similarity (Hebbia Matrix). GraphRAG community summaries for cross-corpus themes, deferred until the vault exceeds roughly a million tokens. Late chunking as an alternative to contextual retrieval, pick one. Plain-file durability: metadata in the file, queryable like a database (Obsidian Dataview).

**Literature and public data.** Semantic Scholar bulk search and Recommendations API (free key, 1 request/s; live test today returned 525 hits for "enhanced oil recovery polymer" since 2025), Crossref `from-index-date`, OpenAlex (paid tier for `from_updated_date`), arXiv OAI-PMH nightly. OnePetro terms forbid systematic retrieval and crawling: mine metadata and abstracts only, store individually licensed PDFs as third-party data under their subscription tag, never republish. A living-review pipeline (fetch → embed → threshold against topic anchors → dedupe → publish) is a near drop-in (acc-ml-living-review). Elicit-style extraction of paper facts into fixed columns. Regulator feeds with real endpoints: Colombia ANH via Socrata (`datos.gov.co/resource/fdvb-hsrf.json`, 53k rows live), Brazil ANP monthly per-well CSVs, Argentina CKAN datastore (5 req/s hard limit), Peru Perupetro Excel downloads (no API), Venezuela via OPEC secondary sources only, US SEC `data.sec.gov` company facts and EIA API v2.

**Memory, skills and cost.** Tiered memory: a small always-in-context core index plus a searchable archive (Letta, Claude Code auto-memory). Hooks are enforcement, `CLAUDE.md` is guidance. Prompt caching (cache reads at 0.1× or less) and the Batch API (50% off) as the first cost levers. Plan with a frontier model, implement with cheaper workers, gated by tests: Cursor's swarm experiment ran at roughly a fifteenth of the single-frontier cost with full test pass; Anthropic's data shows orchestration helps on decomposable work and hurts on single dependent chains. Cheap models fail on multi-file refactors and forgotten requirements (SWE-Bench ProMax averages 11 files per task, best model 41%); price on the hardest tenth of tasks. Spec-driven development (Spec Kit, Kiro requirements/design/tasks) with contract-derived tests. Static per-module model assignment beats a runtime router for a build. Cloudflare Access is free for up to 50 users; Render static sites have no auth; Supabase Pro gives Postgres, pgvector, storage and row-level security for USD 25 a month; Cloudflare R2 has no egress fees.
