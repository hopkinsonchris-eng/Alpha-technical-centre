# Wave 2 — Phase 1 Practice Scan: the Opportunity-centred Hub

Researched 30 Sep 2026 after the first live day on the platform. Brief: re-centre the
Hub on the Opportunity Register (world map → country → projects → project file),
put the tools in a toolbar that opens in the context of the current project, and
fix what the first live use showed (raw-JSON record panel that breaks the iPad
layout, legacy and experimental tools in the Today catalog, placeholder APEX
versions). Wave 1 practices P1–P12 are in `../02-practice-scan.md`; numbering
continues from P13.

Direct domain: upstream data platforms (Wood Mackenzie Lens, Rystad UCube,
Seequent Central). Adjacent domains: clinical context management (HL7 CCOW),
enterprise ontology apps (Palantir Foundry), CRM record pages (Salesforce),
developer portals (Backstage), legal document management (iManage), product
tools (Linear), open cartography (Natural Earth, Leaflet).

## What we have today (for the "cost" column)

- `opportunity-register.html` is a public-site tool: MapLibre map with a
  schematic SVG fallback, demo data in `localStorage`, a `/api/opportunities`
  fetch that no Vault route serves, and `vault.saveRun()` for its calculations.
- Vault `projects` has `id, client_id, name, status, default_legal_tag,
  asset_ids[], members[]`. No country, no coordinates, no stage. `assets`
  already has `kind='country'` and a `country` column.
- The Hub is five pages (`index`, `project`, `tool`, `search`, `queue`,
  `analogues`, `cost`, `settings`) sharing `hub.js`; the tool page opens a tool
  with `?project=` already; the record panel is `jsonText()` in a 520 px column
  that only floats at ≥1200 px, so on an iPad it lands inside the page flow.
- `catalog.json` lists every manifest; `hub.js` renders `experimental` and
  `deprecated` as pills but does not hide them; external APEX versions are
  hand-typed placeholders.

## The ten that matter

| # | Practice | Who does it | Why it is good (evidence) | Cost to adopt here |
|---|---|---|---|---|
| P13 | **Map-first navigation: the world map is the front door.** Countries are coloured by what the firm holds there; a click opens the country with its assets ranked; a second click opens the asset. Search, filter and map are the same list. | Wood Mackenzie Lens Upstream (5,600+ assets, 180 countries, "search, filter and map assets on a detailed mapping interface") | People remember where work was, not what it was called. Geography is the one index every partner already carries in their head, and it is the same for a Venezuelan cluster and a Kazakh brownfield. https://www.woodmac.com/lens/upstream/ | Low–medium. `assets` already has `kind='country'`; add `country` and `lat/lon` to `projects`; one Hub page draws Natural Earth countries (P19) with counts from `/api/projects`. |
| P14 | **One shared context, and every application follows it.** A context manager holds "the current patient"; when the user changes it in one app, every open app switches. The context is a small tuple (patient id, encounter, user), set bi-directionally. | HL7 CCOW context management (published 1999, still the standard behind clinical desktops) | This is exactly "the tools should open whatever project you are in": the Hub becomes the context manager, the toolbar's tools are the participants, and a tool that saves a run tags it with the context it was opened in. https://www.hl7.org/implement/standards/product_brief.cfm?product_id=1 | Low. `hub.js` keeps `{project, opportunity, country}` in the URL and `sessionStorage`; the toolbar passes `?project=` to browser tools and the same id to APEX apps via their existing key link; `vault-client.js` already reads `project`. |
| P15 | **A record page is a highlights strip, related-list cards and an activity timeline, never raw fields.** A compact layout picks the 5–7 fields for the top strip; related objects are cards with counts; everything that happened is one chronological feed. | Salesforce Lightning record page (compact layouts drive the highlights panel; activity timeline replaces the old activity lists) | The record panel we shipped shows `JSON.stringify` because nothing told it what matters. Naming the highlight fields per record type (run, item, dispatch, opportunity) fixes the screen and the iPad layout in one go. https://trailhead.salesforce.com/content/learn/modules/lex_customization/lex_customization_compact_layouts · https://help.salesforce.com/s/articleView?language=en_US&id=sales.activity_timeline_parent.htm&type=5 | Low. A `renderRecord(kind, record)` in `project.js` with a highlight list per kind and a details drawer; the panel becomes a sheet below 1200 px. |
| P16 | **Pivot through linked objects; the actions menu is populated from the object you are on.** From a project, pivot to its runs, documents, contacts, analogues; every view offers only the actions that apply to the selected object type. | Palantir Foundry Object Explorer ("pivot to linked objects… through multiple links"; Actions dropdown "automatically populated with applicable" actions) | Turns the Hub from pages into a graph you can walk: country → project → run → the letter that quoted it → the client. The toolbar is an actions menu whose entries are the tools whose manifests declare they accept a project. https://www.palantir.com/docs/foundry/object-explorer/pivot-linked · https://www.palantir.com/docs/foundry/action-types/use-actions | Medium. Tool manifests gain `context: ['project','opportunity']`; a `related` block on the project page lists linked objects with counts from existing routes (`/api/runs?project=`, `/api/items?project=`, `/api/dispatches?project=`). |
| P17 | **Lifecycle is a required field of every catalog entry, owned by the component's own repo, and the catalog shows `production` by default.** `experimental` and `deprecated` exist but sit behind a filter; the entry is read from the component's own `catalog-info.yaml`, not typed centrally. | Backstage software catalog (`spec.lifecycle` required; values experimental / production / deprecated) | Fixes both findings from today at the root: the Today page hides non-production tools unless asked, and external APEX apps publish their own version file that the catalog reads, so the placeholder goes away when the developer ships one line. https://backstage.io/docs/features/software-catalog/descriptor-format/ | Low. `hub.js` catalog filter defaults to `production`; `catalog.json` build reads `https://<apex-app>/version.json` when present and marks the row "version: as published by the app" or "unverified". |
| P18 | **Matter-centric workspace: the matter is the only container; documents, email, tasks and people are filed into it, and every screen opens inside it.** | iManage Work (matters as "cabinet dividers", all contracts, correspondence and due-diligence in one workspace) | We adopted email filing (P9) but the Hub still starts from a tool list. Making the opportunity the workspace means an associate never has to know which tool made a number, only which opportunity it belongs to. https://registration.imanage.com/pages/organizing-your-files-in-imanage-work | Low. Conceptual: the opportunity id and the project id become the same id (an opportunity is a project with `status='prospect'`), so `projects` is the register. |
| P19 | **Public-domain country polygons, no tile server, no API key.** Natural Earth 1:110m Admin 0 countries as GeoJSON (~800 KB, ~230 KB gzipped), keyed by ISO A2, drawn as SVG or with Leaflet; choropleth by a per-country value. | Natural Earth (public domain) · Leaflet country plugins · topojson/world-atlas | The register's MapLibre map needs a tile provider and today falls back to a schematic SVG when tiles fail behind Access. A self-hosted GeoJSON works offline, on iPad, behind Cloudflare Access, and can be styled in house colours. https://www.naturalearthdata.com/downloads/110m-cultural-vectors/110m-admin-0-countries/ · https://github.com/topojson/world-atlas | Low. One static file under `hub/geo/`; ~150 lines of SVG projection code (equirectangular is enough for a click map), or Leaflet from cdnjs if pan/zoom is wanted. |
| P20 | **A context-aware command menu (Cmd+K): the actions for the selected object come first, then navigation, then everything else.** | Linear command menu ("once an issue is selected, Cmd+K… select the preferred action"; context-sensitive) | The same idea as P16 for the keyboard: from anywhere in the Hub, type a country, an opportunity or a tool and land in context. Cheap to add once P14 holds the context. https://linear.app/docs/select-issues · https://www.storylane.io/tutorials/how-to-use-linears-command-menu | Low–medium. One overlay in `hub.js` fed by `/api/projects`, the catalog and the country list; deferred if the toolbar covers the need. |
| P21 | **A project is a timeline of revisions with stages; alternative hypotheses live on branches and are preserved, never overwritten; decisions are auditable from the history.** | Seequent Central (revisions, branching, stage categorisation, event logs) | Our runs are already immutable and superseded (rule 9). Showing an opportunity as a timeline of runs, documents and dispatches, with its stage changes, is the "history of when and why decisions were made" that Central sells. https://help.seequent.com/Central/en-GB/Content/guides/branches.htm · https://www.seequent.com/central-project-versioning-and-chronology-for-model-comparison/ | Low. A `stage` column and `stage_history` on `projects`; the timeline is the activity feed of P15 fed by `audit_events` and `runs`. |
| P22 | **Screen, rank and compare across the whole portfolio from one table: production, reserves, economics at country, company or field level; benchmark two assets side by side.** | Rystad UCube / E&P Analysis Dashboard; S&P Vantage | The register already ranks by uplift share and risk score in one page; the Hub should do it across everything the Vault knows (runs, analogue rows, price decks) so a partner can answer "which two should we push this quarter" without opening a tool. https://www.rystadenergy.com/services/upstream-solution | Medium. A `/api/projects/rank` route joining projects, latest run outputs and analogue rows; a compare view for two ids. Second wave candidate. |

## Not adopted (considered and set aside)

- **Live MapLibre tiles for the Hub map.** Needs a tile provider key served to the browser (rule 5 territory) and fails behind Access; P19 covers the need.
- **Full Foundry-style ontology editor.** We have the ontology in `docs/vault-hub/schemas/`; the win is the pivot and action pattern (P16), not an editor.
- **Server-side CCOW-style context manager.** The browser tab is the only participant set that matters today; URL and `sessionStorage` are enough (P14).
