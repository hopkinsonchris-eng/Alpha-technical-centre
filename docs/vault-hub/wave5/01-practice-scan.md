# Wave 5 — Practice Scan: the project file you work from

Tooler phase 1, 2 October 2026. Brief from Chris Hopkinson: "I want the hub to load everything, find everything, load that, remember everything and never forget." The first live use showed three doors missing: you cannot look at an original file in the Hub, you cannot ask the Hub to write from what it knows, and the Claude app on the iPad cannot reach the Vault at all.

## What the code says before any practice is adopted

- **Originals on Render live on the container's own disk.** `VAULT_STORAGE` defaults to the filesystem, the Supabase storage backend is a stub, and `render.yml` attaches no disk. A file uploaded to the live Vault is lost at the next deploy; its text and chunks survive in Postgres. The research and miner crons also write originals, so a disk on one service would not do: the store must be shared.
- **The MCP endpoint is live** (`POST /mcp`, stateless Streamable HTTP) behind Cloudflare Access, with seven tools. The Claude app cannot present an Access login or a service token, and a shared token would defeat per-person scope (rule 4).
- **The drafter exists** (`POST /api/draft`: email, letter, report section, calc note, cited to records, open questions and who to ask, saved as a note, rendered to letterhead) but the Hub has no door to it, and it reads neither the register counterparties nor the research findings (F17).

## The scan (direct analogues and three adjacent domains: data rooms and legal DMS, source-grounded writing and clinical sign-off, app connectors)

| # | practice | who does it | why it's good | cost to adopt (this stack) |
|---|---|---|---|---|
| P40 | Serve originals only through a scope-checked route, `no-store`, every view audited | iManage, NetDocuments, every data room | Confidentiality stays structural; "who viewed what" comes free | Low: one route, `isVisible`, `audit.ts` |
| P41 | Render PDFs with PDF.js on canvas, never in an iframe; images inline; everything else downloads with `Content-Disposition: attachment` | GitHub, Dropbox, Nutrient | iPad Safari shows only page one of an embedded PDF; a canvas viewer works; iOS canvas memory needs lazy pages | Medium: pdfjs-dist from cdnjs, lazy rendering, clamp canvas pixels |
| P42 | Spreadsheets as HTML tables per sheet (SheetJS), row-capped, with sheet tabs | GitHub, SheetJS | Native, selectable, bilingual chrome; no server work | Low |
| P43 | Word and PowerPoint converted to PDF server-side, cached by content hash | Dropbox, NetDocuments, Datasite | One viewer, true fidelity | High: LibreOffice/Gotenberg service (512 MB+) or a paid API; client-side renderers are approximations |
| P44 | Citation chips per sentence that open the exact passage, not just the record title | NotebookLM, Elicit, Lexis+ | The common failure is a claim broader than its passage; the reviewer must see the words | Low: the drafter returns record ids per sentence; a bottom-sheet pane on iPad |
| P45 | "What this draft does not know" shown before the body, each question linked to who to ask; uncited sentences highlighted and blocking approval until cited, deleted or marked the author's own | Claim-locked reporting, NewsLabs, Shepard's Verify | Turns "never state a figure the Vault cannot cite" into a UI invariant | Low: the API already separates cited from uncited and lists questions |
| P46 | Per-paragraph accept, accept with comment, reject; tone and length as bounded buttons; save to the file first, send as a separate confirmed act; the sent version immutable with the review decisions as its audit log; a soft warning on a sign-off that opened no citation | Harvey, Spellbook, Outlook Copilot, Gmail, Clio, NetDocuments, clinical scribes | Keeps the person as author, records why, and matches rule 9 | Medium: paragraph state in the page, a review record posted back, render after acceptance |
| P47 | Recipient from the contact graph with role, organisation and last contact; warn when outside the project's scope; the draft grounded in prior correspondence with the records it read listed | Affinity, Attio, Outlook Copilot | Right person, no contradiction of an earlier letter, no confidentiality slip | Medium: contact picker over the visible contacts; the counterparties from wave 4 addendum 2 feed it |
| P48 | OAuth 2.1 with PKCE for the connector, scoped to the signed-in person; discovery by 401 + `resource_metadata`; Claude's published client identity or dynamic registration; the existing login (Cloudflare Access) as the upstream | Notion, Atlassian, Anthropic's connector guide | The only auth the hosted Claude app accepts; per-person scope and audit survive; Cloudflare's own "Managed OAuth" route has an open failure against the web and mobile app (claude-ai-mcp #410) | High: a small authorisation server in the Vault (metadata, authorize behind Access, token, refresh), `/mcp` and the token endpoint bypassing Access, bearer validation |
| P49 | Read tools auto-run, write tools prompt (`readOnlyHint`, titles, namespaced names, "new hire" descriptions); search-then-fetch with stable refs and a Hub link; a `get_project_context` tool (brief, counterparties, recent records, open questions); every write files back a superseding record and returns its ref; per-person rate limits | Notion, GitHub remote MCP, Anthropic's writing-tools and context-engineering guides | The Vault, not the chat, is the memory; nothing lives only in a conversation | Low to medium: annotate the seven tools, add `get_item`, `get_project_context`, `file_item` |

Not adopted: dynamic watermarks and fenced view (for external parties, not staff); Microsoft and Google online viewers (need a public URL and cache the file on their servers); tokens in the connector URL (prohibited by Anthropic); a shared service token for the connector (one credential for everyone).

## Hard constraints that bind the choices

- Custom connectors: Pro, Max, Team and Enterprise (Free: one). On Team and Enterprise an Owner adds the connector; each member then signs in. Claude connects from Anthropic's cloud, so the Vault and its authorisation endpoints must be reachable from the public internet; OAuth endpoints must answer within 10 s. Auth settings on a connector cannot be edited after creation. A connector added in claude.ai appears in Claude Code under the same account.
- iPad Safari: no embedded PDF beyond page one; canvas memory caps; PDF.js range requests unreliable on Safari (fetch the whole file under about 20 MB).
- The storage interface returns whole objects; a 100 MB scan is loaded into memory per view until a range read is added.
