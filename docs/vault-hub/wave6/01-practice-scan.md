# Wave 6 — Practice Scan: everything in

Tooler phase 1, 4 October 2026. Brief from Chris Hopkinson, rolled up from the first live week: "I want the hub to load everything, find everything, load that, remember everything and never forget." The Vault can now view, cite, write and remember, but it holds only what one person uploads by hand. Three asks were added on 4 October: when someone signs into the Hub with their alpha-technical-centre address, ask them then to approve access to their mailbox; once in, the Hub should stop disconnecting unless the device changes; and the admin should not have to collect credentials from anyone.

## What the code says before any practice is adopted

- **Mail capture is built and idle.** `vault/src/ingest/mail/` has two sources that yield one `RawMessage` (IMAP for Zoho with per-person app passwords, Gmail over its REST API with an OAuth refresh token), capture with Message-Id and content dedupe, thread grouping by References, a classifier with four signals and evidence (contact 0.5, domain 0.35, thread 0.3, tokens 0.2; files at 0.85, else the filing queue with suggestions), dispatches in and out, organisation proposals, an exclusion list (`mail_exclusions`: addresses, domains, labels), a five-minute poll cron and a backfill command. Every source is configured from environment variables on the server (`ZOHO_MAIL_IMAP_USER_n` / `_PASSWORD_n`, up to nine). Nothing is configured on the live service, so the cron runs and captures nothing.
- **There is no per-person consent and no mailbox table.** A person cannot connect their own mailbox; an admin cannot mint an app password for someone else (Zoho app passwords are personal); the Zoho Mail REST API, which would take a per-person OAuth grant, has no adapter. The Vault already is an OAuth *server* (wave 5) and already is an OAuth *client* of Zoho for WorkDrive and Books (`zoho-auth.ts`, one refresh token in env each).
- **WorkDrive and Books sync exist** (`workdrive.ts` lists mapped team folders by modified time; `zoho-books.ts` pulls invoices, purchase orders and expenses by modified time) and are idle for the same reason: no token on the server and an example-only `master/workdrive-map.json`.
- **The filing queue works but has never had a message in it.** `hub/queue.html` lists unfiled messages with up to three suggested projects, Assign (which also adds the sender as a project contact, so the next message files itself) and Not a project email; the same page reviews organisation, asset, research and NDA-expiry proposals. The Today page has a Filing queue card that links there. What it lacks is any sense of volume: a backfill of years of mail would put thousands of rows in it on day one.
- **Nothing says what came in.** The `jobs` table records each poll run; no page shows "since you last looked: 14 emails filed, 3 waiting, 2 invoices, 1 new organisation".
- **Sessions.** The Hub is behind Cloudflare Access; the application session length is whatever the application was created with (24 hours by default). Safari Private tabs discard the Access cookie when closed. Both are settings, not code. The Claude connector's refresh tokens already last 30 days and roll over on use.
