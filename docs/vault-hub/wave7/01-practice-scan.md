# Wave 7 — Practice Scan: an indispensable Hub

Tooler phase 1, 5 October 2026. Brief from Chris Hopkinson: set up a team of four, a debugging expert who tests every function to failure and writes the snag list, a UI expert who checks that every screen responds, is clear and obvious and visually impactful, a data expert who checks that the hierarchy flows the way petroleum engineers think with important data to the fore and legacy data behind, and a "next big thing" expert who proposes step changes such as a country opening pack (hydrocarbon law, licence rounds and their process, operators, the service industry) assembled when a project opens in a new country. The goal: the Hub as an indispensable tool for every ATC team member. "Tooler everything."

- `02-ui-review.md` (UI): per-page findings at desktop, iPad and phone, 14 ranked recommendations R1 to R14 with BEFORE → AFTER, four signature ideas A to D; 59 screenshots under `evidence/ui-*.png`.
- `03-data-hierarchy.md` (data): the hierarchy as the tables link it, ten places the model and the UI disagree, three journeys traced in code, every record kind classed as foreground, background or archive, additive schema changes A1 to A10, API changes S1 to S10, Hub changes H1 to H8, age rules G1 to G7, a priority five.

## What the code says before any practice is adopted

- **Two blockers stop an engineer on day one.** The first and fourth tools in the project toolbar (Opportunity Register, APEX Reservoir 3D) redirect to the legacy Staff Portal login whose own banner says it is going, and lose the `?project=` context (S13; `opportunity-register.html:21`, `reservoir-simulator.html:349`). No route or screen creates a client legal tag, so every project is firm-tagged and the confidentiality model the Hub promises does not hold (S1); this is the root of Find returning another project's document for any query in any scope (S30; `search.ts:36`, `scope.ts:58-67`).
- **The Vault's main content is invisible to Find and to the numbers.** Runs are never indexed (S31; `ingest/index.ts:108`); every tool saves runs as `draft` and the headline numbers, scorecard and own-evaluation analogue rows read only `final`, with no route to promote (03 §1.3; `projects.routes.ts:195-196`, `nodal-analysis-tool.html:1365`). "My projects" cards show dashes because `/api/projects` ignores `?mine=1` and returns no counts (S2; `hub.js:401-427`).
- **Nowhere states stage · next action · last activity in one line.** On the project file "Next step" sits about 1,000 px down below a two-row launcher of nine tool chips, and the timeline starts at 1,700 px on desktop and 2,900 px on a phone; Today is a 4,274 px scroll (8,464 on a phone) whose first screen is the globe and four country rows with nothing to act on (02 §1, R1, R4). The sidebar changes per page, so Queues, Analogues and Cost are unreachable from Today (S3, R3).
- **The hierarchy stops at field in practice.** Basin, block, reservoir and well exist only as enum values; `assets.parent_id` is never written by any Hub path; the nodal, simulator and financial tools save no asset ids, so a run never names a well (03 §1.1; `001_init.sql:78-80`, `hub/project.js:432-441`). Counterparties are split between contact rows and free text in the register. There are no deadlines anywhere in the Vault except invoice due dates, and no per-project "since you last looked".
- **A figure never ages unless a cited run is superseded.** Reference-set staleness is a stub (`staleness.ts:146-149`), so a new price deck never stales an NPV although tools declare `consumes: price_deck`; the country brief has no maximum age; register figures carry no unit or date (03 §7.2). Automatic research can bury a project's eight records under 22 marginal papers in the timeline and lineage (S17; `queries.ts:78`).
- **The outward half does not exist.** The Hub captures, cites, drafts and remembers what the firm holds, but on day one in a new country the engineer still assembles the law, the round, the fiscal terms, the operators, the regulator and the data room by hand in Safari (04 §0). The wave 4 research runner, the ingest snapshots with sha256 manifests, citation enforcement (`checkCitations`), the jobs table and pgvector chunks are the plumbing a pack needs and already exist.
- **What is already good.** AA contrast on every token measured, gold focus ring, skip link, reduced motion, full EN/ES static coverage; the queue, the search results page and the tool page read well; the globe is the strongest brand asset; the citation, supersession and nightly staleness machinery is sound (02 §1, 03 §7.1).

## Hard constraints that bind the choices

- **Source licences.** NSTA: free, perpetual, commercial use allowed, a mandatory attribution line, no API key. Sodir: NLOD with a third-party-data caveat and a Cloudflare challenge on the technical page. ANH: 2,000 records per request. Argentina CKAN: HTTP only. ResourceContracts: CC BY-SA, so derived fiscal tables carry share-alike and stay in the public-scope pack rather than merging into confidential records. EITI and GEM: CC BY 4.0. EIA: public domain. IEA datasets: not open. OnePetro: full text prohibited. Mexico, Namibia and Guyana: no open feed reachable, manual seeding.
- **Provider.** The Anthropic web fetch tool fetches only URLs already in the conversation and warns of exfiltration beside sensitive data, so the pack passes only the registry's public URLs and never client records; sections are drafted from stored originals with citations enforced, and an empty section is shown as empty. Costs at current prices: one to two pounds per country build, about thirty pence per refresh, under a weekly budget.
- **Tier A schemas cannot change.** No well or as-of on the run record (use `asset_ids` and facets), no expected-reply date on dispatches (milestones keyed by dispatch id), no country scope for lessons, no research or dossier item type (03 §6). Everything proposed is additive.
- **Confidentiality.** The pack is `lt-public` and built from public sources only; the firm's country brief stays scope-cached beside it; `isVisible` governs every read; hide, never delete.
- **Immutability.** Runs and items are never overwritten: a run becomes `final` by a status route on the row's already-mutable status column, not by a new row (03 A5, S7).
- **Public pages stay byte-identical.** Everything here lives under `/hub`, `/api` and the Vault; the Staff Portal gate on two tool pages is removed without changing the public sitemap.
